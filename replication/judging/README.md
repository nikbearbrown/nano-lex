# Judging: how models and people judge agreement between lexicon editions

This folder supports the agreement study in [../AGREEMENT-METHOD.md](../AGREEMENT-METHOD.md). Several language models each draft their own independent edition of the NanoLex nanomedicine lexicon (977 seed terms in [../../data/seeds.tsv](../../data/seeds.tsv), one record per `concept_id`, in the gen-v2 JSON shape of [../instructions.md](../instructions.md)). None of them sees the initial NanoLex of 2024–2025; that lexicon joins the comparison afterwards as one more edition, named `legacy`. Judges compare two editions' entries for the same term and say how far they **mean** the same thing. The kit was adapted from the agreement kit of the Drugs and Recreational Drug Use Lexicon (`nikbearbrown/drugs-and-recreational-drug-use-lexicon`, branch `grok-agreement-method`), itself ported through the clinical lexicon from the Irreducibly Human Work Lexicon's kit (78f889a2); its domain rules were replaced by this repository's.

| You are | Read |
|---|---|
| A **person** asked to judge (about 100 items, a few hours) | [HUMAN-JUDGE-INSTRUCTIONS.md](HUMAN-JUDGE-INSTRUCTIONS.md) |
| An **operator** starting an AI judge | [START-HERE-AI-JUDGE.md](START-HERE-AI-JUDGE.md): **one generic prompt** for any model, plus the chat-only steps |
| An **AI judge** (Codex, Claude, Grok, a chat model, or a future model) | [AI-JUDGE-INSTRUCTIONS.md](AI-JUDGE-INSTRUCTIONS.md) |
| An **AI agent running a person's session** (the person said "I'm a human judge") | [INTERVIEWER-PROTOCOL.md](INTERVIEWER-PROTOCOL.md) |

All three use **one output schema** ([judgment.schema.json](judgment.schema.json)) and **one validator**:

```bash
python3 replication/scripts/agreement.py validate RUN_DIR --judge-id YOUR_JUDGE_ID
```

## The pieces

| Path | What it is |
|---|---|
| `prompts/system.txt`, `prompts/P1.txt` … `prompts/P6.txt` | The exact judge prompts (AGREEMENT-METHOD.md 4.2), adapted to this lexicon's scope; the system prompt carries the domain rule (descriptive only; no preparation protocols, doses or clinical advice; no verdicts on whether something works). Every request already carries its rendered `system` and `user` text. |
| `judgment.schema.json` | The one result-line schema, for models and people alike |
| `RUN_DIR/requests/<stage>/batch-NNNN.jsonl` | Every blinded request (written by `agreement.py run`) |
| `<PRIVATE>/keys/anon.jsonl` | Which edition is A and which is B. **Never committed here** (it is gitignored and kept privately by the operator). Only `stats` and registering new model judges need it. |
| `drafters.tsv` | Which models drafted which editions. `join` reads it for self-exclusion. |
| `RUN_DIR/requests/exclusions.json` | Obfuscated self-exclusion index (judges don't open it) |
| `RUN_DIR/judges.json` | Registered human judges |
| `RUN_DIR/results/<judge id>/judge.json` | A model judge's identity: provider, model name, **exact version** (required, or flagged as unknown), and the model string as the harness reports it. The judge id is `<provider>-<model name>-<version>`, for example `anthropic-claude-fable-5-2`. |
| `RUN_DIR/packets/<judge id>/batch-NNNN.jsonl` | An AI judge's work, generated by `join`, with self-exclusion applied |
| `RUN_DIR/humans/<judge_id>/sample.jsonl`, `progress.json` | A person's seeded sample and where they stopped |
| `RUN_DIR/results/<judge_id>/...` | What a judge hands in |

`RUN_DIR` is the run folder Bear names (none is built yet; the first will be `replication/agreement/pilot-test`, made with `agreement.py run` once the editions are frozen). Drafts and run folders are never committed here (see [../../AGENTS.md](../../AGENTS.md)); `run` reads them from private paths and writes edition-naming files only to `--private-dir`. Results are committed on a branch `judging/<judge id>` and pushed. Nothing is ever pushed to `main`, and nothing is force-pushed.

## Rules everyone follows

- **Blind.** Never open the keys, any edition's drafts or private run folder, any branch or folder holding drafts, any copy of the initial NanoLex (it is not in this repository), `lexicon/entries.jsonl` once it exists, or another judge's `results/`. Judge only what the packet or sample shows.
- **Descriptive only.** Entries say what a nanomedicine term names. Judges compare meanings; they never add preparation protocols, doses or clinical advice, and never judge whether a material, product or treatment works or is safe.
- **No personal details.** No judge, model or person ever writes, requests or uses details of an identifiable person's health. An item that appears to contain such details is labelled `UNSURE` with the note "possible personal information" and reported to the operator, without repeating it.
- **Self-exclusion.** A model never judges an item that involves an edition it drafted. Registration enforces this (AI-JUDGE-INSTRUCTIONS.md, section 2).
- **Independence.** Judge each item on its own. Don't compare your answers with anyone else's.
- **Meaning, not wording.** Two texts agree if they say the same thing, however differently they say it.
